## What It Is

The FORA MCP Server is a convenience interface layer that exposes ExchangeService RPCs as MCP tools. Any AI agent with MCP support can discover and access resources without custom SDK integration -- just add the MCP server to the agent's tool configuration.

The MCP server is a **thin proxy**, not a performance layer. It translates simplified MCP tool calls into full FORA protocol messages, forwards them to an Exchange via Connect-Go, and translates responses back into agent-friendly JSON. High-throughput production workloads use gRPC/Connect directly (via the [Agent SDK](/components/agent-sdk/overview/) or [Broker](/components/broker/overview/)).

**Value proposition**: Zero-SDK resource access. An agent operator adds a server entry to their MCP config, sets an API key, and the agent gains six tools. No dependency, no generated code, no FORA-specific client library.

## MCP Tools

| Tool | Maps To | Scope | Description |
|---|---|---|---|
| `discover_supply` | `DiscoverResources` | `fora:discover` | Search for content offers by URI |
| `execute_transaction` | `ExecuteTransaction` | `fora:transact` | Commit to offers and receive delivery info |
| `report_usage` | `ReportUsage` | `fora:report` | File a post-usage report |
| `dispute_transaction` | `DisputeTransaction` | `fora:report` | File a content dispute |
| `check_health` | (synthetic) | `fora:discover` | Check Exchange connectivity |
| `get_rate_limit_status` | (synthetic) | `fora:discover` | Return cached rate limit info |

The MCP server auto-populates protocol fields that agents should not need to know about: `ver`, `id` (ULID), and `aisystem` (from OAuth context). It also signs each outbound request with its proxy Ed25519 key as an RFC 9421 HTTP Message Signature in the HTTP headers.

## Input Simplification

A full `ResourceQuery` proto has 12 fields. The `discover_supply` tool has 3:

```json
{
  "uris": ["https://example.com/article-1"],
  "functions": ["inference", "summary"],
  "deadline_ms": 500
}
```

The MCP server bridges the gap -- translating simplified JSON inputs into full proto messages and stripping internal fields from responses.

## Authentication Model

The MCP server uses a **delegated proxy key** model:

```
Agent --OAuth 2.1--> MCP Server --Ed25519 signed request--> Exchange
```

- Agents authenticate to the MCP server via **OAuth 2.1**
- The MCP server signs outbound requests with its own registered Ed25519 key
- The Exchange knows both who signed (proxy) and on whose behalf (agent from OAuth claims)

### Scopes

| Scope | Tools Allowed | Description |
|---|---|---|
| `fora:discover` | `discover_supply`, `check_health`, `get_rate_limit_status` | Read-only discovery |
| `fora:transact` | `execute_transaction` | Financial commitment |
| `fora:report` | `report_usage`, `dispute_transaction` | Post-transaction reporting |

An agent with `fora:discover` only can search and evaluate offers without committing to transactions.

## Deployment

### Local (stdio) -- Claude Desktop

Add to `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "fora": {
      "command": "fora-mcp-server",
      "args": ["--transport", "stdio"],
      "env": {
        "FORA_EXCHANGE_URL": "https://exchange.example.com",
        "FORA_PROXY_KEY_PATH": "/path/to/ed25519-private.pem",
        "FORA_OAUTH_TOKEN": "eyJhbGciOi..."
      }
    }
  }
}
```

### Remote (Streamable HTTP)

For shared deployment behind a load balancer:

```bash
fora-mcp-server \
  --transport http \
  --listen :8080 \
  --exchange-url https://exchange.example.com \
  --proxy-key-path /secrets/ed25519-private.pem \
  --oauth-jwks-url https://auth.example.com/.well-known/jwks.json
```

The MCP server is fully stateless -- no database, no persistent storage. Deploy N replicas behind a load balancer with no session affinity required.

## Schema Generation

Tool definitions are generated from `fora.proto` via `protoc-gen-go-mcp`. Zero schema duplication -- if the proto changes, tool schemas update automatically on rebuild. The MCP server never manually defines tool input/output schemas.

## What Is NOT Exposed

The MCP server exposes agent-facing RPCs only. Provider onboarding (`RequestDomainVerification`, `ConfirmDomainVerification`), CatalogService RPCs, and internal protocol fields (signatures, `ext` payloads) are deliberately excluded.
