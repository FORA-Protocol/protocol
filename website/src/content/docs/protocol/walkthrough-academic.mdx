> Complete walkthrough of a 50-paper academic literature review using FORA v1.0. Demonstrates batch DOI queries, mixed free/paid/subscription offers, retraction detection, and the `fora-academic-v1` extension profile. Every field name and message structure matches the current `fora.proto`.

## Scenario

A university AI research agent needs 50 academic papers for a literature review on "transformer architectures in medical imaging." The papers span four sources:

| Source | Type | Papers | Pricing |
|---|---|---|---|
| **Northfield Preprints** | Open Access (Gold) | 12 | Free |
| **University subscription** | Institutional deal via Corvid Scientific | 20 | $0.00 (subscription) |
| **Corvid Scientific** (outside the subscription) | Paywalled | 2 | $1.50/article |
| **Halden Academic** | Paywalled | 15 | $1.50/article |
| **Halden Academic** | Paywalled, retracted | 1 | $1.50/article (flagged) |

The agent carries a delegation JWT from the university, granting `academic:*` and the subscription scope `subscription:inst-sub-calderhill-2026`. The subscription term is gated behind that delegation, and the Exchange honors a delegation only on a request the agent signs itself, so the agent queries the Exchange directly for the papers the Broker found only at a price. The Broker resolves DOIs via OpenAlex, discovers Exchanges via `fora.json`, and uses the `fora-academic-v1` extension profile to access version, OA status, and retraction metadata.

**Seven-step flow:**

```
Discovery → ResourceQuery (Broker-led) → ResourceResponse → Direct ResourceQuery with the delegation → Agent Selection → Batch ExecuteTransaction → ReportUsage
```

All three publishers route through the same academic aggregator Exchange (`exchange.scholarsgate.example`). This is the aggregator-as-Exchange pattern: academic aggregators (like Semantic Scholar, OpenAlex, or a commercial equivalent) already normalize metadata across publishers. FORA gives them a standard protocol for what they already do. The Broker sends a single batch query instead of querying each publisher separately.

## Step 2 — ResourceQuery (Broker-led)

The Broker sends a batch `ResourceQuery` with all 50 DOIs in `ResourceQuery.uris`. The `Requester` states the agent's scopes, the university's subscription scope among them, and carries the university's delegation token (the shared chain case `docs_walkthrough_academic`), which the Exchange does not honor on a query the Broker originated (see below). The query declares support for `fora-academic-v1` so the Exchange includes version, OA status, and retraction metadata in its response.

**Key fields in this request:**

- **`ResourceQuery.uris`** — 50 DOIs in `doi:` URI scheme. The Exchange resolves these against its catalog. DOIs are the universal dedup key for academic content: the same paper on Northfield Preprints and Corvid Scientific shares the same DOI (or is linked via `academic.related_works`).
- **`requester.scopes`** — the agent's own statement: `academic:*` for full academic access, and `subscription:inst-sub-calderhill-2026` for the university's subscription. The Exchange does not verify them, and they decide only which non-gated terms are presented. The subscription term is gated behind a verified delegation, so stating its scope does not present it ([Scope-Based Access](/protocol/authentication/#scope-based-access)).
- **`delegation`** — A root token in the [delegation profile](/protocol/authentication/#delegation), signed by `calderhill.example`'s Ed25519 key. Decoded, its header and claims contain:
  ```json
  // protected header
  { "alg": "EdDSA", "typ": "fora-delegation+jwt" }
  // claims
  {
    "iss": "calderhill.example",
    "sub": "inst-sub-calderhill-2026",
    "aud": ["exchange.scholarsgate.example"],
    "jti": "inst-sub-calderhill-2026-0193",
    "scope": "academic:* subscription:inst-sub-calderhill-2026",
    "exp": 1798761599,
    "cnf": { "jkt": "ASNiAESsPqu7dXM58L6CaoKlLdEUXLTnbPJkhHij_yE" }
  }
  ```
  The monthly access quota is not a token claim: the Exchange meters it on the subscription record and reports it in `subscription_quota`.
  On this query the Exchange does not honor the delegation: the Broker originated the query and signs it alone, so nothing on it can pass the holder binding, and the Exchange answers as if no delegation were present ([Which signature binds in a brokered request](/protocol/authentication/#verification)). The subscription term is therefore hidden from this answer, as if it did not exist. In Step 4 the agent queries the Exchange directly, signing the query itself, and the delegation is verified there, offline and with no call to Calder Hill.
- **`supported_profiles`** — `["fora-academic-v1"]` tells the Exchange to include academic-specific `ext` fields (OA status, version, retraction status) and attestation claims. Without this declaration, the Exchange MAY skip expensive metadata computation like retraction checking.

**What the Broker learns from the 50 OfferGroups:**

### Offer Categories

The Exchange classified each of the 50 DOIs into one of three categories based on the publisher's access model; the subscription term cannot appear on this query:

| Category | Count | Pricing Model | Rate | Key Signal |
|---|---|---|---|---|

### Extension Profile Fields (`fora-academic-v1`)

Because the ResourceQuery declared `supported_profiles: ["fora-academic-v1"]`, every offer includes academic-specific metadata:

- **`academic.oa_status`** — Open Access classification. Values: `gold` (fully OA), `green` (author self-archived), `hybrid` (OA in subscription journal), `bronze` (free-to-read but no license), `diamond` (no APC), `closed` (paywalled). The agent can use this to prefer free sources.
- **`academic.version`** — Article lifecycle stage. Values: `preprint` (author's original), `aam` (accepted author manuscript), `vor` (Version of Record, publisher-formatted). The Broker puts VoR first when available, then the preprint.
- **`academic.retraction_status`** — Publication integrity status. Values: `active` (valid), `retracted` (withdrawn), `expression_of_concern` (under investigation). When `retracted` appears in `ext_critical`, the consumer MUST understand retraction semantics or reject the offer.
- **`academic.peer_review_status`** — Whether the paper has been peer-reviewed. Values: `peer_reviewed`, `not_peer_reviewed`. Useful for weighting evidence quality.

### Retraction Flagging

The retracted paper (DOI `10.5555/hmeth.2024.02467`) is immediately identifiable:

1. **Attestation claim**: `academic.retraction_status: "retracted"` in `ResourceAttestation.claims`, signed by `haldenacademic.example`.
2. **Ext field**: `academic.retraction_status: "retracted"` in `Offer.ext`.
3. **Critical signaling**: `ext_critical: ["academic.retraction_status"]` — the consumer MUST understand retraction semantics. An agent that does not support `fora-academic-v1` does not use this offer, rather than silently consuming a retracted paper.
4. **Offer.title**: Prefixed with "RETRACTED:" as a human-readable signal.

### Content Identity and Dedup

Every offer carries a `ResourceIdentity` with:
- **`doi`** — The DOI serves as the universal dedup key. If the same paper were available from multiple Exchanges (e.g., via a different aggregator), the Broker groups offers by DOI, so the agent sees every offer for the paper together.
- **`content_hash`** — SHA-256 hash for post-delivery verification. Because `resource_mutability` is `RESOURCE_MUTABILITY_STATIC` for all academic papers (published articles do not change — corrections and retractions create new resources), the agent SHOULD verify the hash on delivery.
- **`canonical_url`** — The publisher's authoritative URL. Different from the DOI URI but resolves to the same resource.

- **`subscription_unit_value`**: $1.50 on each subscription item. This is the imputed value for accounting purposes (ASC 606 prepaid drawdown). Calder Hill's subscription is "spending" this value even though the marginal cost is zero.
- **`subscription_quota`**: After the transaction, 76,500 accesses remain (20 were consumed from the previous 76,520). The quota resets on April 1.
- **Signed URLs**: Each URL is valid for 5 minutes (`expires_at`), contains the `agent_identity_hash` to prevent URL sharing, and is recorded by its hash for three-sided reconciliation (agent, Exchange, CDN).

The agent then fetches all 49 PDFs via the signed URLs. For each paper, because `resource_mutability` is `RESOURCE_MUTABILITY_STATIC`, the agent computes SHA-256 of the delivered PDF and compares against the `identity.content_hash` from the offer. A mismatch would be grounds for a `DisputeTransaction`.

## Step 7 — ReportUsage

Usage reporting is mandatory for all 49 transactions. A usage report settles one transaction, so the agent files one report per transaction: 49 reports. Each report states consumption in the unit of that item's offer. The 12 Northfield Preprints and 20 Corvid Scientific subscription offers are priced in `tokens`, so their reports carry token counts. The 17 paid offers are priced per access, so each of their reports carries one access. Here is the report for the paid nucleus-segmentation paper:

`POST https://exchange.scholarsgate.example/fora/v1/fora.v1.ExchangeService/ReportUsage`

{/* fora-validate: UsageReport */}
```json
{
  "ver": "1.0",
  "exchange": "exchange.scholarsgate.example",
  "idempotency_key": "ur-litrev-halden-001",
  "transaction_id": "txn-halden-paid-001",
  "billing_id": "bill-halden-paid-001",
  "usage": {
    "function": ["ai-input"],
    "consumed_quantity": 1,
    "consumed_unit": "accesses",
    "displayed_to_user": true,
    "citation_included": true
  },
  "timestamp": "2026-03-20T13:00:00Z",
  "assets": [
    {
      "uri": "doi:10.5555/hmeth.2024.02401",
      "title": "Patch-Level Transformers for Nucleus Segmentation in Whole-Slide Images",
      "package_id": "PKG-HALDEN-HMETH-02401"
    }
  ]
}
```

Response:

```json
{
  "report_id": "rpt-litrev-001"
}
```

**Reporting details:**

- **`consumed_quantity: 1`, `consumed_unit: "accesses"`** — the unit matches the offer's `pricing.unit`. The offer's estimate was 1 access at $1.50, so the purchase charged 1 × $1.50 = $1.50, and that charge is final. A report is never refused because its quantity differs from the estimate.
- **`citation_included: true`** — the literature review includes proper citations for all 49 papers. This is relevant for publishers who offer attribution-only pricing or require citation as a license condition.
- **`assets`** — names the paper the transaction covers, so the Exchange can attribute usage to its publisher. Across the 49 reports, Corvid Scientific sees 20 accesses against Calder Hill's subscription, the paid publishers see 17 paid accesses, and Northfield Preprints sees 12 free accesses.
- **`report_id: "rpt-litrev-001"`** — enables the dispute chain. If this paper's content hash had not matched on delivery, the agent would reference this report when filing a `DisputeTransaction`.

## Protocol Summary

| Step | RPC | Free OA (12) | Subscription (20) | Paid (17) | Retracted (1) |
|------|-----|---|---|---|---|
| 1 | -- | `fora.json` discovery | `fora.json` discovery | `fora.json` discovery | `fora.json` discovery |
| 2 | `DiscoverResources` (Broker-led) | `Requester` stating `academic:*` | Subscription term hidden: the delegation is not honored on the Broker's query | Same | Same |
| 3 | -- | Offers at $0, `oa_status: "gold"` | Paid offers at $1.50 only | Offers at $1.50 | Offer with `retraction_status: "retracted"` in `ext_critical` |
| 4 | `DiscoverResources` (direct, with the delegation) | -- | Delegation verified; offers at $0, `subscription_id` set | Unchanged, $1.50 | -- |
| 5 | -- | Agent selects (free) | Agent selects (free via sub) | Agent selects (its cost policy) | Broker flags; agent excludes |
| 6 | `ExecuteTransaction` | Batch, cost $0 | Batch, cost $0, sub quota decremented | Batch, cost $1.50/ea | Not transacted |
| 7 | `ReportUsage` | One report per transaction, in tokens | One report per transaction, in tokens | One report per transaction, 1 access each | No report |

**Authentication at every step:**
- **Agent to Exchange**: signed with an RFC 9421 HTTP Message Signature (alg=ed25519) in the HTTP headers
- **Institutional delegation**: delegation JWT signed by `calderhill.example`'s Ed25519 key, holder-of-key bound via `cnf.jkt` (offline-verifiable), verified on the agent's direct query and direct purchase, not honored on the Broker's query
- **Exchange to Agent**: `exchange_signature` on each Offer (Ed25519, stateless verification)
- **Signed URLs**: Ed25519 (Exchange-signed, publicly verifiable, agent identity bound)
- **Content integrity**: SHA-256 hash verification on all 49 delivered PDFs (`RESOURCE_MUTABILITY_STATIC`)

**Key academic-specific capabilities demonstrated:**
- **DOI as universal dedup key** -- cross-exchange resource identification
- **Mixed pricing in single batch** -- FREE + subscription (FREE + subscription scope) + PER_UNIT in one transaction
- **Institutional subscription** -- hidden on the Broker's query, presented on the agent's direct query once the delegation JWT is verified offline, no call to Calder Hill
- **Retraction flagging via `ext_critical`** -- consumers MUST understand retraction semantics or reject
- **`fora-academic-v1` profile** -- OA status, version lifecycle, peer review status, retraction metadata
- **Aggregator as Exchange** -- one Exchange serves content from multiple publishers
